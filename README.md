# Setzkasten

HEEx components and design system for Phoenix admin backends: the shared component library of a
handful of small Phoenix apps (a home-automation dashboard, a CMS admin, a portfolio tracker, a
budgeting app).

The name is a typesetter's type case: ready pieces to compose pages from.

- 28 function components (buttons, fields, alerts, tables, lists, modals, app shell, …) with `attr`/`slot`
  declarations and docs.
- daisyUI 5 themes `zipfel-light` / `zipfel-dark` plus accessibility patches in one CSS file.
- No Bootstrap JS: native `<dialog>` and `<details>`, `Phoenix.LiveView.JS`, two colocated hooks.
- Works under a strict CSP: no inline styles.
- Design rules: [guides/design-system.md](guides/design-system.md).

## Install in a Phoenix 1.8 app

The steps assume an app generated by `phx_new` 1.8 (Tailwind 4 and daisyUI through the `tailwind` hex
package and the `daisyui` dependency). An app without Tailwind first adds those from a fresh `phx.new`
project: `{:tailwind, "~> 0.5", runtime: Mix.env() == :dev}`, the `:daisyui` dependency, `config :tailwind`
(version `4.3.3`, `NODE_PATH` env) and the `tailwind` watcher.

1. Add the dependency in `mix.exs`, then `mix deps.get`:

   ```elixir
   {:setzkasten, github: "shostakovich/setzkasten"}
   # or a local checkout: {:setzkasten, path: "../setzkasten"}
   ```

2. `assets/css/app.css`: keep the daisyUI plugin with `themes: false`, remove the two generated
   `daisyui-theme` blocks and the generated `@custom-variant dark` line, then import the package CSS after
   the plugin:

   ```css
   @import "tailwindcss" source(none);
   @source "../css";
   @source "../js";
   @source "../../lib/my_app_web";

   @plugin "daisyui/packages/bundle/daisyui" {
     themes: false;
   }

   @import "lib/setzkasten/priv/static/setzkasten.css";
   ```

   The import resolves through the generated tailwind `NODE_PATH`, which holds `Mix.Project.build_path()`
   (`_build/<env>`): Mix links every dependency's `priv` to `_build/<env>/lib/<dep>/priv`, so the same line
   works for path, git and hex dependencies and in every environment, with no machine-specific path in the
   app. The link exists once the dependency is compiled: the generated `assets.build` alias compiles
   first, and the generated Dockerfile runs `mix compile` before `mix assets.deploy`.

   The package CSS contains `@source "../../lib"`, so Tailwind scans the components' classes without an
   extra line in the app (Tailwind follows the `priv` link to the package checkout). It also defines the
   `dark:` variant and the `phx-*-loading` variants; drop the generated copies.

3. `assets/js/app.js`: register the package's colocated hooks next to the app's:

   ```js
   import {hooks as colocatedHooks} from "phoenix-colocated/my_app"
   import {hooks as setzkastenHooks} from "phoenix-colocated/setzkasten"

   const liveSocket = new LiveSocket("/live", Socket, {
     hooks: {...colocatedHooks, ...setzkastenHooks},
     // ...
   })
   ```

   This resolves through the generated esbuild `NODE_PATH` (`Mix.Project.build_path()`), for path and hex
   dependencies alike. Run `mix compile` before `esbuild` in deploy aliases (generated aliases already do).

4. Import the components where the app imports its core components (`lib/my_app_web.ex`,
   `html_helpers/0`):

   ```elixir
   use Setzkasten
   ```

   Then delete the generated duplicates, which would clash: in `CoreComponents` `flash/1`, `button/1`,
   `input/1`, `header/1`, `table/1`, `list/1`, `icon/1` (and `error/1` if nothing else uses it); in
   `Layouts` `flash_group/1` and `theme_toggle/1`. Keep `translate_error/1`, `translate_errors/2`,
   `show/2`, `hide/2`. Replace `hero-*` icon names with Lucide names (step 6).

5. Root layout (`root.html.heex`): replace the generated theme script with

   ```heex
   <.theme_meta />
   <.theme_script nonce={assigns[:csp_nonce]} />
   ```

   and do not set `data-theme` on `<html>` unless the person chose a theme (server-stored choice:
   `data-theme="zipfel-light"` or `"zipfel-dark"`). Give `<body>` `class="bg-base-100 text-base-content"`.
   Render `<.flash_group flash={@flash} />` and one `<.confirm_dialog />` in the app layout.

6. Configure (all optional, `config/config.exs`):

   ```elixir
   config :setzkasten,
     icons: MyAppWeb.Icons,                                  # Lucide icons the app uses
     plush: MyAppWeb.Plush,                                  # plush image sources
     translate_error: {MyAppWeb.CoreComponents, :translate_error}
   ```

   Icons: copy the SVG files from [lucide-static](https://www.npmjs.com/package/lucide-static)
   (`icons/<name>.svg`, ISC licence) into e.g. `assets/vendor/lucide/` and compile them:

   ```elixir
   defmodule MyAppWeb.Icons do
     use Setzkasten.Icons, path: "assets/vendor/lucide"
   end
   ```

   Plush: a module implementing `Setzkasten.Plush` (`src(name, :light | :dark)`), see its docs.

### Alert tint

Soft alerts mix 25 % of their tone into the background in the light theme and 8 % (daisyUI's default)
in the dark theme. To go back to 8 % in light mode as well, add to `app.css` after the import:

```css
@layer base {
  :where(:root), [data-theme="zipfel-light"] { --setzkasten-alert-tint: 8%; }
}
```

## Catalog

```sh
mix deps.get
mix dev     # http://localhost:4110 (PORT=… to change)
```

A small Phoenix endpoint in `dev/` (compiled only in dev and test, not shipped) renders every component with
its variants and states, light and dark, plus three composed screens under `/screens/…`. It is the target
for screenshots, contrast checks and visual regression. The first run downloads Tailwind 4.3.3 and
esbuild 0.25.4.

Setzkasten is built for its author's own apps and changes whenever they need something. That makes

welcome, though. Take it, bend it to your apps, and if you come up with something good, don't be
surprised if the best ideas get stolen back.
